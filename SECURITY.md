# Security Policy

The MigrDB team takes the security of our library and users seriously. We appreciate your efforts to responsibly disclose vulnerabilities.

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |
| < 0.1.0 | :x:                |

We strongly encourage all users to stay updated with the latest stable releases.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

If you believe you have discovered a security vulnerability in MigrDB, please disclose it responsibly using one of the following methods:

1. **Email (Preferred)**:
   Send an encrypted or detailed report directly to:
   📧 **[muchammadtedy99@gmail.com](mailto:muchammadtedy99@gmail.com)**

2. **GitHub Security Advisory**:
   You can also submit a confidential report through GitHub's [Private Vulnerability Reporting](https://github.com/MuchammadTedyA/migradb/security/advisories/new) feature on the repository.

### What to Include in Your Report
To help us triage and resolve the issue quickly, please provide:
- A clear description of the vulnerability and its potential impact.
- Step-by-step instructions or a minimal Proof of Concept (PoC) demonstrating how to trigger the issue.
- Details of affected components (e.g., Rust core, Go bindings, Node.js bindings, Python bindings, or model codegen).
- Any proposed remediation or patches, if available.

### Response Process
- We will acknowledge receipt of your vulnerability report within **48 hours**.
- We will provide a status update including an assessment of impact and planned resolution timeline.
- Once a fix is verified, a patched release will be published and credit will be given in the security advisory (unless you request anonymity).
